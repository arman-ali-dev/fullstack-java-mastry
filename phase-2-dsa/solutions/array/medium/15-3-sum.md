# 3 Sum

## Pattern

Sorting + Two Pointers

---

## Optimal Approach

### Code

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> ans = new ArrayList<>();
        int n = nums.length;

        for (int i = 0; i < n; i++) {

            if (i != 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            int left = i + 1;
            int right = n - 1;

            while (left < right) {
                int result = nums[left] + nums[right] + nums[i];

                if (result == 0) {
                    ans.add(new ArrayList<>(List.of(nums[i], nums[left], nums[right])));
                    left++;
                    right--;

                    while (left < right && nums[left] == nums[left - 1]) {
                        left++;
                    }
                } else if (result < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }

        return ans;
    }
}
```

### Time Complexity

- O(n²)

### Space Complexity

- O(n)

### Explanation

My first thought was the brute-force approach, where I could check every possible triplet using three nested loops. Although it guarantees the correct answer, its time complexity is O(n³), which is too slow for large inputs.
<br>
To optimize it, I first sort the array. Then, I fix one element at a time and use the Two Pointers technique to find the other two elements. Since the array is sorted, I place one pointer just after the fixed element and the other at the end of the array. I calculate the sum of these three elements. If the sum is zero, I add the triplet to the answer, move both pointers, and skip duplicate values to avoid adding the same triplet again. If the sum is smaller than zero, I move the left pointer to increase the sum, and if the sum is greater than zero, I move the right pointer to decrease it. I also skip duplicate fixed elements before starting the two-pointer search. This approach efficiently finds all unique triplets with O(n²) time complexity while avoiding duplicate results.
